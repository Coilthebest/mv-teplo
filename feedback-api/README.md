# Отзывы Teplo с подтверждением почты

Статические страницы сами по себе письма не отправляют. Сначала подключите отправителя и сервер, затем публикуйте новый интерфейс. Пока сервер отвечает старым протоколом или отправитель не настроен, новая форма заблокирована; старые опубликованные сообщения остаются видны.

## Бесплатный отправитель

1. Зарегистрироваться на https://resend.com/signup, тариф Free.
2. Domains → Add domain → `mail.mv-teplo.ru`. Добавить показанные Resend записи DNS в панели домена; дождаться Verified. Не менять записи сайта и существующие MX корневого домена.
3. Создать ключ с правами Sending access только для этого домена.
4. В переменные существующей функции Яндекс добавить `FEEDBACK_EMAIL_API_KEY` (ключ Resend) и `FEEDBACK_EMAIL_FROM` = `Teplo <noreply@mail.mv-teplo.ru>`. Ключ хранить только на сервере.

На момент подготовки бесплатный тариф Resend: 3 000 писем в месяц, не более 100 в день. Проверка: https://resend.com/pricing . Объём и доступность тарифа могут меняться.

## Обновление функции без замены оплаты и генерации

Скачать именно текущие исходники рабочей функции из Яндекс Cloud и сохранить резервную копию. Выполнить `node feedback-api/install.cjs /путь/к/копии-функции`. Установщик заменяет только `feedback.js` и таблицу маршрутов в `index.js`, остальные файлы сохраняются.

При работе через редактор: заменить содержимое `feedback.js` файлом из этой папки. В `index.js` заменить единственную строку `const feedbackRoutes = ...` на:

```js
const feedbackRoutes = {feedback:'list','feedback-submit':'submit','feedback-verify':'verify','feedback-admin':'admin','feedback-moderation':'moderate'};
```

Опубликовать новую версию с прежними точкой входа `index.handler`, файловым хранилищем `/function/storage/teplo-hd` и всеми прежними переменными. Код рассчитан на Node.js 22 и существующий модуль `telegram.js`.

Затем опубликовать новые `index.html`, `feedback.js`, `feedback.css`, `feedback-admin.html`, `feedback-confirm.html` из этой ветки на mv-teplo.ru. Ссылка из письма ведёт на `feedback-confirm.html`; человек нажимает явную кнопку, чтобы почтовые сканеры не подтверждали сообщение автоматически. GET-запрос не подтверждает сообщение.

## Кабинет владельца

Открыть прежнее уведомление о сообщении в личном Telegram → ссылку модерации → «Открыть все сообщения». Новые подтверждённые сообщения также содержат ссылку на кабинет. Адрес имеет секрет после `#`; публично его не размещать. После открытия секрет убирается из адресной строки и живёт только до закрытия/перезагрузки страницы. Фильтры: все, отзывы, предложения, вопросы. «Скрыть с сайта» убирает публикацию, «Опубликовать» возвращает её. Исходник и ответ сохраняются. Новые сообщения без подтверждения нельзя публиковать. Старые отзывы сохраняются без выдуманных оценок и адресов; в среднее не входят.

## Проверка

`node --test feedback-api/test.cjs`

Тесты используют временное хранилище, поддельную почту и Telegram, реальные сообщения не отправляются. Проверены подтверждение, повторные запросы, срок ссылки, запрет публикации до подтверждения, ограничение частоты, скрытие/восстановление, старые ссылки и маскирование адреса. Перед включением в продакшене нужен реальный тест: письмо на собственный адрес → подтверждение → Telegram → публикация → скрытие → восстановление. Проверить получение на Mail.ru, Яндекс и Gmail. При сбое Telegram человек может повторить подтверждение той же ссылкой; успех показывается после доставки уведомления.
