# Отзывы Teplo с подтверждением почты через Yandex Cloud Postbox

Статические страницы сами по себе письма не отправляют. Сначала подключите Postbox и сервер, затем публикуйте новый интерфейс. Пока сервер отвечает старым протоколом или отправитель не настроен, новая форма заблокирована; старые опубликованные сообщения остаются видны.

## Отправитель

В каталоге сайта создать адрес Postbox для `mail.mv-teplo.ru`, подпись DKIM — «Простая». Ограничить список отправителей адресом `noreply@mail.mv-teplo.ru`. Добавить обе полученные CNAME-записи у текущего DNS-провайдера, режим DNS only; дождаться Success.

Назначить существующему сервисному аккаунту функции роль `postbox.sender` в этом же каталоге. В переменные функции добавить только `FEEDBACK_EMAIL_FROM` = `Teplo <noreply@mail.mv-teplo.ru>`. Статические ключи и Resend не нужны: временный IAM-токен берётся из контекста каждого вызова функции и передаётся напрямую в Postbox по HTTPS в заголовке `X-YaCloud-SubjectToken`. Он не сохраняется и не возвращается браузеру.

На момент подготовки первые 2 000 исходящих писем в календарном месяце бесплатны; стандартная квота нового облака — 200 писем за сутки. Проверка: https://yandex.cloud/ru/docs/postbox/pricing . Функции и хранилище тарифицируются отдельно.

## Обновление функции без замены оплаты и генерации

Скачать именно текущие исходники рабочей функции из Яндекс Cloud и сохранить резервную копию. Выполнить `node feedback-api/install.cjs /путь/к/копии-функции`. Установщик заменяет только `feedback.js`, таблицу маршрутов отзывов и передачу временного токена в `index.js`, остальные файлы сохраняются. Повторное применение безопасно.

При работе через редактор: заменить содержимое `feedback.js` файлом из этой папки. В `index.js` заменить единственную строку `const feedbackRoutes = ...` на:

```js
const feedbackRoutes = {feedback:'list','feedback-submit':'submit','feedback-verify':'verify','feedback-admin':'admin','feedback-moderation':'moderate'};
```

В этом же обработчике заменить вызовы:

```js
feedback.list(mount,process.env,context?.token?.access_token)
feedback[operation](body,mount,process.env,ip,context?.token?.access_token)
```

Опубликовать новую версию с прежними точкой входа `index.handler`, сервисным аккаунтом, файловым хранилищем `/function/storage/teplo-hd` и всеми прежними переменными. Код рассчитан на Node.js 22 и существующий модуль `telegram.js`.

Затем опубликовать новые `index.html`, `feedback.js`, `feedback.css`, `feedback-admin.html`, `feedback-confirm.html` из этой ветки на mv-teplo.ru. Ссылка из письма ведёт на `feedback-confirm.html`; человек нажимает явную кнопку, чтобы почтовые сканеры не подтверждали сообщение автоматически. GET-запрос не подтверждает сообщение.

## Кабинет владельца

Открыть прежнее уведомление о сообщении в личном Telegram → ссылку модерации → «Открыть все сообщения». Новые подтверждённые сообщения также содержат ссылку на кабинет. Адрес имеет секрет после `#`; публично его не размещать. После открытия секрет убирается из адресной строки и живёт только до закрытия/перезагрузки страницы. Фильтры: все, отзывы, предложения, вопросы. «Скрыть с сайта» убирает публикацию, «Опубликовать» возвращает её. Исходник и ответ сохраняются. Новые сообщения без подтверждения нельзя публиковать. Старые отзывы сохраняются без выдуманных оценок и адресов; в среднее не входят.

## Проверка

`node --test feedback-api/test.cjs`

Тесты используют временное хранилище, поддельные Postbox и Telegram, реальные сообщения не отправляются. Проверены контракт Postbox и передача IAM-токена, подтверждение, повторные запросы, срок ссылки, запрет публикации до подтверждения, ограничение частоты, скрытие/восстановление, старые ссылки и маскирование адреса. Перед включением в продакшене нужен реальный тест: письмо на собственный адрес → подтверждение → Telegram → публикация → скрытие → восстановление. Проверить получение на Mail.ru, Яндекс и Gmail. При сетевом таймауте Postbox повторная попытка может доставить ещё одно письмо с той же ссылкой; подтверждение после успешной доставки Telegram повторно уведомление не создаёт. При сбое Telegram человек может повторить подтверждение той же ссылкой; успех показывается после доставки уведомления.
